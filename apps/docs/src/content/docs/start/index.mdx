QueryWeave is a framework-independent, type-safe URL state engine. It gives one description of what
a query means, and reuses that description everywhere the query travels: a browser history stack, an
incoming request, a router, a test.

## The problem

A URL query is the only application state that is simultaneously a string, a user-visible artifact,
a navigation event, a shareable link, and an input from outside your program. Most codebases end up
describing it more than once:

- a parser in the client component that reads `page` as a number,
- a second parser on the server that reads it again,
- a serializer somewhere else that writes it back,
- and a default value repeated in all three.

Those descriptions drift. The server accepts `page=0`, the client does not. A link built by hand
produces `?sort=name&page=1` while the application produces `?page=1&sort=name`, and the two cache
differently. Nothing is broken enough to fail loudly, and everything is slightly wrong.

## What QueryWeave does

A **query model** describes a complete query state once. Every parameter in it owns both directions
of translation, so decoding and encoding cannot drift apart.

```ts
import { defineQueryModel, param } from "@queryweave/core";

const products = defineQueryModel({
  search: param.text().optional(),
  page: param.integer({ min: 1 }).default(1),
  sort: param.choice(["name", "created_at", "price"]).default("created_at"),
});
```

That model is a value. It has no environment, no reactivity, and no navigation policy. It can be
decoded on a server, encoded into a link, bound to a component, or asserted against in a test —
without changing.

## What QueryWeave guarantees

- **A value equal to its declared default is omitted from canonical output.** Two states that mean
  the same thing produce the same URL.
- **An invalid value recovers to its default or to `undefined`, and reports an issue.** It never
  disappears silently and never throws.
- **Repeated keys survive.** A query is never reduced to `Record<string, string>`, because
  `?tag=a&tag=b` carries meaning.
- **A transition encodes once, navigates once, and notifies once.**
- **Query keys the model does not manage are preserved** by the runtime, so QueryWeave can be
  adopted for part of a URL.

## What QueryWeave does not do

- It does not schedule, throttle, coalesce, or cancel transitions. Every operation is applied
  immediately. This is deliberate and recorded in [ADR 0004](https://github.com/queryweave/queryweave/blob/main/docs/adr/0004-runtime-transitions-and-adapters.md).
- It does not bundle a validation library. Validators join through
  [Standard Schema](/validation/).
- It does not decide navigation policy inside a codec, and it does not let an adapter decode.
