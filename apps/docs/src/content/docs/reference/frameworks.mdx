## @queryweave/vue

### `useQueryModel(model, options?)`

```ts
function useQueryModel<TDefs>(
  model: QueryModel<TDefs>,
  options?: UseQueryModelOptions<TDefs>,
): QueryModelBinding<TDefs>;
```

`UseQueryModelOptions` is `{ adapter?, navigation?, runtime? }`. The adapter is resolved in that
order: an explicit `adapter`, then the injected one, and an existing `runtime` bypasses both. If
none is available, it throws with a message naming all three.

### `QueryModelBinding`

| Member                                            | Type                                                     |
| ------------------------------------------------- | -------------------------------------------------------- |
| `runtime`                                         | `QueryRuntime<TDefs>`                                    |
| `values`                                          | `Readonly<QueryModelValues<TDefs>>` — reactive, readonly |
| `status`                                          | `"valid" \| "invalid"` — a plain property                |
| `issues`                                          | `readonly QueryIssue[]` — a plain property               |
| `field(key, options?)`                            | `WritableComputedRef<Values[key]>`                       |
| `update` `replace` `remove` `reset` `transaction` | the runtime's operations                                 |

`values`, `status`, and `issues` are plain properties, not refs, so templates read them without
`.value`. Watching them requires a getter: `watch(() => binding.status, ...)`.

`QueryFieldOptions` is `{ navigation? }`.

### Injection

```ts
function provideQueryAdapter(adapter: QueryAdapter): void;
function injectQueryAdapter(): QueryAdapter | undefined;
const queryAdapterKey: InjectionKey<QueryAdapter>;
```

`queryAdapterKey` is `Symbol.for("queryweave.adapter")`, exported so other packages — including
`@queryweave/nuxt` — can install an adapter without importing the binding.

### Lifecycle

Inside an effect scope, the binding registers `onScopeDispose` to unsubscribe, and disposes the
runtime only if it created one. A binding given a `runtime` never disposes it.

## @queryweave/vue-router

### `createVueRouterAdapter(router, options?)`

```ts
function createVueRouterAdapter(
  router: Router,
  options?: VueRouterAdapterOptions,
): VueRouterQueryAdapter;
```

`VueRouterAdapterOptions` is `{ onNavigationFailure? }`, called with a
`VueRouterNavigationOutcome`:

```ts
type VueRouterNavigationOutcome =
  { readonly ok: true } | { readonly ok: false; readonly failure: NavigationFailure | Error };
```

`VueRouterQueryAdapter` is a `QueryAdapter` plus `readonly router: Router` and `dispose(): void`.

Transitions use `router.push` and `router.replace`, preserving the current `path` and `hash`. A
refused or redirected navigation is reported through `onNavigationFailure` rather than thrown.
Change notification comes from a watcher on `route.fullPath`, attached on first subscription, so one
transition still produces one notification.

Repeated keys round-trip through Vue Router's array query form; a `null` query value — the router's
representation of a valueless key — becomes an empty string entry.

## @queryweave/nuxt

### Module

```ts
export default defineNuxtModule<QueryWeaveModuleOptions>({ ... });
```

`QueryWeaveModuleOptions` is `{ autoImports?: boolean; enabled?: boolean }`, both defaulting to
`true`, configured under the `queryweave` key of `nuxt.config`. Compatible with Nuxt 4 and above.

With `autoImports`, `useQueryModel` and `provideQueryAdapter` are auto-imported from
`@queryweave/vue`. With `enabled: false`, nothing is registered.

### Runtime entry point

```ts
// @queryweave/nuxt/runtime
function createNuxtQueryAdapter(router: Router): VueRouterQueryAdapter;
function installQueryAdapter(app: App, adapter: QueryAdapter): void;
```

`installQueryAdapter` accepts any adapter, so an application can substitute its own. The registered
plugin also exposes the adapter as `$queryWeaveAdapter` on the Nuxt app.

The runtime plugin creates one adapter per Vue application instance — one per request on the
server. Nothing is stored at module scope.

## @queryweave/standard-schema

### `fromStandardSchema(schema, options?)`

```ts
function fromStandardSchema<TSchema extends StandardSchemaV1>(
  schema: TSchema,
  options?: StandardSchemaRefinementOptions,
): StandardSchemaRefinement<TSchema>;
```

`StandardSchemaRefinementOptions` is `{ name? }`, defaulting to the schema's own vendor string.

The returned refinement's input and output types are inferred from the schema, so a transforming
schema changes the parameter's value type. Vendor issues are mapped onto QueryWeave's shape and
reported as `validation_failed`; a vendor's own error type is never exposed. Asynchronous schemas
resolve through `model.decodeAsync`.

This package depends on `@standard-schema/spec` — types only — and on no validator.
