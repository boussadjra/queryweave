## What it owns

One thing: turning a Node `IncomingMessage` into an absolute `URL`. Everything after that is
delegated to [`@queryweave/server`](/adapters/server/), so decoding lives in exactly one place.

## What it does not own

Decoding, validation, defaults, navigation, and any HTTP framework. Express, Fastify, NestJS, and
Hono are not dependencies and never will be — they all expose a request object this package can
read.

## Install

```sh
pnpm add @queryweave/core @queryweave/server @queryweave/node
```

## Example

```ts {6-7,9-10}
import { createServer } from "node:http";

import { readNodeQuery } from "@queryweave/node";

createServer((request, response) => {
  const result = readNodeQuery(request, products);
  const values = result.ok ? result.value : { ...products.defaults(), ...result.partial };

  response.writeHead(200, { "content-type": "application/json" });
  response.end(JSON.stringify({ values, issues: result.issues }));
}).listen(3000);
```

## Resolving the URL

A Node request carries a path, not an absolute URL, so the authority has to come from somewhere:

```ts {3-4,6-7}
import { resolveNodeRequestUrl } from "@queryweave/node";

resolveNodeRequestUrl(request);
// http://<host header>/products?page=2

resolveNodeRequestUrl(request, { host: "example.com", protocol: "https" });
// https://example.com/products?page=2
```

The order of precedence is: explicit options, then forwarded headers _if you opted in_, then the
`host` header, then the HTTP/2 `:authority` pseudo-header, then the fallback host
`queryweave.invalid`. The scheme follows `x-forwarded-proto` (opt-in), `:scheme`, then the socket:
`https` when it is encrypted, `http` otherwise.

The path comes from `originalUrl` when a framework set it — Express strips a mounted router's
prefix from `url` and keeps the full path there — and from `url` otherwise. A target such as
`//evil.example/p` stays a path on the request's own host rather than becoming a different origin,
and a `Host` header that cannot form a URL falls back instead of throwing.

<Aside type="caution" title="Forwarded headers are off by default">
`x-forwarded-host` and `x-forwarded-proto` are attacker-controlled unless a trusted proxy sets them.
They are ignored unless you pass `trustForwardedHeaders: true`, which you should do only when a
proxy you control is guaranteed to overwrite them.

```ts {1,3-4}
const result = readNodeQuery(request, products, { trustForwardedHeaders: true });

result.ok; // true for ?search=vue&page=2
if (result.ok) result.value.page; // 2
```

Only the query is decoded, so the authority does not affect the values — but it does affect any URL
you build from the result.

</Aside>

## A request-scoped source

```ts {3-5}
import { createNodeQuerySource } from "@queryweave/node";

const source = createNodeQuerySource(request);
source.read(); // "?page=2"
source.request; // the original IncomingMessage
```

## Asynchronous validation

```ts {1,3-5}
const result = await readNodeQueryAsync(request, products);

const values = result.ok ? result.value : { ...products.defaults(), ...result.partial };
const rows = await searchProducts(values);
result.issues; // keep normalized validation issues for logging
```

Same rule as everywhere else: use the asynchronous form when a parameter or the model uses an
asynchronous refinement.

## Edge cases

- **A request with no URL** resolves to `/`.
- **An absolute-form request line** (`GET http://origin.test/p`) is used as given; explicit `host`
  and `protocol` options still override its authority.
- **A comma-separated forwarded header** uses the first entry, trimmed.
- **An empty header value** is ignored rather than producing an empty host.
- **The fallback host is `queryweave.invalid`**, chosen because `.invalid` can never resolve.
- **Fastify and Koa** hand you a wrapper; pass `request.raw` (Fastify) or `ctx.req` (Koa), which is
  the underlying `IncomingMessage`. Express and Hono's Node adapter pass it through directly.

## How it is tested

`tests/node/node.test.ts` covers URL resolution, header precedence, the forwarded-header opt-in,
HTTP/2 pseudo-headers, TLS sockets, mounted routers, hostile paths and headers, and decoding. The
